# 产品需求文档：AuditAI 当前实现版

[English guide](implementation.en.md#implemented-capabilities-and-boundaries) · [命名兼容与备份说明](naming-and-backup.md)

更新时间：2026-10-23
适用范围：当前仓库已实现功能。本文不是愿景稿，而是对现有系统能力、约束和验收口径的整理。

## 1. 产品定位

AuditAI 是面向审计人员和审计助理的 AI 协作平台，用于把审计项目材料整理成可核验事实，再基于审计人员确认的事实生成或改写审计报告草稿。

核心价值：

- 把文件、事实、任务、知识库和报告集中到审计项目维度管理。
- 用 Agent 大模型辅助文件解析、事实重解析、翻译、审计底稿生成和 AI 重写。
- 保留审计人员审核、事实确认、版本恢复和系统后台管理能力。
- 降低线上大模型请求过慢、超时和失败对业务流程的影响。

非目标：

- 不替代审计人员事实核验、专业判断和最终签字审核。
- 当前不实现真正的组织/审计机构业务权限体系。组织和审计机构字段只保留兼容与展示/编辑用途。
- 当前不提供客户门户和客户登录协作流程。

## 2. 用户角色

| 角色 | 当前能力 |
|------|----------|
| 审计人员/审计项目用户 | 注册登录、维护个人信息、创建审计项目、上传文件、解析事实、管理知识库、生成报告、管理任务 |
| 系统管理员 | 进入系统后台，查看概览，管理用户和审计项目，重置用户密码，删除用户和审计项目 |
| Agent/Worker | 异步处理文件解析、事实重解析、审计底稿生成、AI 重写、RFI 等后台任务 |
| 组织/审计机构 | 当前仅作为历史兼容壳和用户 `firm_name` 展示/编辑字段，不参与业务筛选和权限 |

## 3. 功能范围

### 3.1 账号与设置

已实现：

- 邮箱注册、登录、刷新登录态。
- 注册时填写公司/审计机构名称；该值保存为用户 `firm_name`。
- 设置页可修改姓名、电话、公司/审计机构名称。
- 修改密码时必须校验当前密码，新密码需二次确认。
- 明亮/暗色主题切换。
- 模型设置页可查看和保存 LLM Provider、Model、Base URL、API Key。
- API Key 不明文回显，只显示是否已配置。
- 设置页可配置告警总开关，并按类别分别控制弹出提示和历史记录。
- 系统管理员邮箱可通过 `SYSTEM_ADMIN_EMAILS` 引导生成。

验收口径：

- 注册后可登录并进入审计项目页。
- 设置页修改公司/审计机构后，系统后台用户列表同步展示。
- 修改 `.env` 中模型配置后，需要重启 API/Worker 才生效。
- 关闭某类弹出提示后，该类操作不再弹 toast；若历史记录仍开启，仍可在告警历史中查询。

### 3.2 审计项目管理

已实现：

- 创建审计项目，填写标题、审计项目类型、客户姓名、客户邮箱、客户电话。
- 客户邮箱和客户电话至少填写一个。
- 审计项目状态流转：接案、事实提取、报告起草、审计人员审核、已提交等。
- 审计项目列表、详情、编辑、软删除、恢复、彻底删除。
- 审计项目列表和详情使用短 TTL 缓存，变更时主动失效。

验收口径：

- 用户只能访问自己是成员的审计项目。
- 删除审计项目后，其文件、事实、任务、报告等相关对象按接口规则进入删除或级联处理。

### 3.3 文件上传与解析

已实现：

- 文件上传后不自动解析，由审计人员手动点击「AI 解析」。
- 点击「AI 解析」后创建后台 Agent 任务，前端不等待模型返回；审计人员可离开页面并在当前审计项目的「Agent 运行记录」查看状态。
- 同一文件存在 `queued/processing` 解析任务时，阻止重复触发。
- 文件类型支持内置类型和用户自定义类型。
- 内置类型包括：审计证据、财务报表、内部控制、合同与协议、会计记录、交易明细、薪酬与人事、外部资料、政策与制度、函证与声明、审计报告、审计询证回复、其他。
- 文件类型设置支持修改显示名称、图标、启用/停用和新增自定义类型。
- 文档解析弹窗支持审计人员提示词、快捷解析重点、知识库引用。
- 解析入口的知识库只使用提示词模板和 Agent 策略；检索只按标题和标签，不按正文内容。
- 解析结果写入事实库。
- 支持下载原始文件、导出当前文档解析事实文本。
- 文档列表支持排序、分页、回收站、恢复、彻底删除。

Agent 解析优化：

- 解析内容有预算控制，避免把超长文档完整塞给大模型。
- PDF 会优先抽取开头和结尾页，减少大文件卡住概率。
- 业务流程（沿用 `resume` 解析分支）采用高召回模式，先生成业务流程分区辅助信息，再通过分块解析、低产出重试和覆盖缺口检查减少漏事实。
- 单次解析最多要求提取有限数量的候选事实，事实会标记为待审计人员审核。
- `内部控制` 有专门提示，重点关注控制目标、控制设计与执行、责任人、审批记录、例外事项和证据依据。
- 长时间未完成的排队或处理中任务会被系统自动标记失败并释放按钮，允许审计人员重新发起。

验收口径：

- 上传 `内部控制` 或自定义类型文件成功。
- 禁用的文件类型不能作为新上传类型。
- 解析失败时文档状态变为失败，前端显示可读错误。
- Agent 运行记录能展示文件名、文件类型、提示词长度、提取事实数、分类统计、文本质量、分块数、覆盖率和失败原因。

### 3.4 事实库

已实现：

- 展示文件解析得到的事实。
- 支持确认、取消确认、编辑、翻译、删除、恢复、彻底删除。
- 点击「有异议」后保持旧风格输入异议；提交重新解析时弹出知识库选择弹窗。
- 事实重解析会创建后台 Agent 任务，结合原事实、异议意见、来源文档文本和选中的知识库参考。
- 同一事实存在 `queued/processing` 重解析任务时，阻止重复触发。
- 事实列表支持排序、回收站和短 TTL 缓存。
- 可从事实创建补材料任务。

验收口径：

- 事实确认状态能被审计底稿生成流程使用。
- 异议重解析不应直接覆盖成不可追溯内容，原始信息应保留在结构化数据中。
- Agent 运行记录能展示事实名、来源文件、异议长度、来源文本长度、知识库引用、原事实和新事实。

### 3.5 知识库

已实现：

- 每个审计人员维护自己名下知识库，不按组织/审计机构共享。
- 类型包括：提示词模板、底稿模板、范文、Agent 策略。
- 支持新增、编辑、筛选、软删除、恢复、彻底删除。
- 文档解析只使用提示词模板和 Agent 策略。
- 审计底稿生成和 AI 重写可使用全部知识库类型。
- 所有入口的知识库检索只依靠标题和标签，避免全文检索导致不透明误选。
- 知识库列表已加入 Redis 缓存，变更后主动失效。

验收口径：

- A 审计人员不能看到 B 审计人员的知识库。
- 搜索时标题或标签命中即可展示，不要求正文命中。

### 3.6 审计底稿生成

已实现：

- 选择事实、知识库、生成策略和提示词后发起审计底稿生成。
- 审计底稿生成走 Celery Worker 异步任务。
- 同一审计项目已有生成任务排队或处理中时，不允许重复发起新的生成任务。
- 生成内容拆分为底稿段落，支持编辑、AI 重写、翻译、导出、删除、恢复、彻底删除。
- AI 重写支持选择事实和知识库参考。
- 底稿段落修改、重写和恢复会保存历史版本。
- 审计底稿生成和 AI 重写的运行状态在当前审计项目的「Agent 运行记录」查看，不再只挂在审计底稿生成页。
- 审计底稿生成、AI 重写中引用的事实依据按普通换行展示，和页面整体风格保持一致。

Agent 生成优化：

- 事实、知识库、用户提示词和输出 token 都有预算限制。
- Worker 会优先组织高置信、已确认或被选中的事实。
- 大模型输出会清理 `<think>` 推理标签。
- 缺少审计项目、底稿段落、事实等必要输入时，Agent 任务标记为失败，不再把错误任务显示成完成。
- 长时间未完成的排队或处理中任务会自动释放，避免按钮永久锁住。

验收口径：

- 生成任务不会因为重复点击产生多条并行生成。
- 生成失败时可在 Agent 运行记录中看到错误。
- 审计人员可恢复历史版本。
- 审计底稿生成记录能展示标题、策略名、事实数量、知识库数量、生成版本；AI 重写记录能展示段落标题、改写要求、事实依据和知识库数量。

### 3.7 Agent 运行记录

已实现：

- 入口位于每个审计项目内，在「审计项目任务」后面，只显示当前审计项目的 Agent 状态。
- 分为三类：文件解析和重解析、事实重解析、审计底稿生成和 AI 重写。
- 支持按更新时间升序/降序切换。
- 前端按每页 10 条分页展示；当前接口默认返回该审计项目最近 20 条 Agent 记录。
- 每条记录展示状态、模型、耗时、创建/更新时间、输入、结果与诊断。
- 文件名、事实名、底稿标题、策略名、知识库标题等关联上下文使用人能阅读的文本展示。
- 机器 ID 会在展示前过滤或压缩，避免普通用户看到难以理解的数据字段。

### 3.8 告警栏与历史查询

已实现：

- 顶部告警栏记录成功和失败提示，支持按全部、成功、失败查看。
- 告警历史支持搜索消息、类别、类型名称和源对象名称。
- 设置页提供告警总开关，并按类别分别控制「弹出」和「历史」。
- 告警类别包括后台任务提交、文件解析、事实重解析、审计底稿生成和 AI 重写、翻译、文档、事实、报告、审计项目任务、知识库、账号与系统等。
- 解析、重解析、审计底稿生成和 AI 重写的提交、完成、失败提示都使用同一个源对象名称，便于审计人员追踪。
- 历史名称优先显示操作源对象，而不是操作本身。例如原始文件名、上传文件类型、事实内容摘要、底稿标题、审计项目名、任务名、知识库标题、用户姓名邮箱或模型名。
- 告警历史用于轻量回看成功/失败结果；复杂 Agent 输入、诊断和错误仍以当前审计项目「Agent 运行记录」为准。

验收口径：

- 文档解析提交、完成或失败时，历史名称显示原始文件名。
- 事实重解析提交、完成或失败时，历史名称显示原事实内容摘要。
- 审计底稿生成、AI 重写、翻译、导出、删除、恢复等操作，历史名称显示对应底稿标题或段落标题。
- 后台任务提交提示不作为单独设置项，而是和其他类别一样支持弹出和历史开关。

### 3.9 翻译

已实现：

- 事实和报告可中英互译。
- 翻译请求有本地内存短缓存，重复翻译同一内容时加速。
- 后端限制输出 token 并使用低温度，降低远端失败率。

验收口径：

- 空内容不触发翻译。
- 翻译失败显示可读错误，不应卡住页面。

### 3.10 任务中心

已实现：

- 侧边栏「任务中心」展示跨审计项目待办。
- 审计项目内「审计项目任务」展示当前审计项目的处理待办和补材料请求。
- 支持新建、编辑、审批、完成、删除、恢复。
- 支持排序和缓存。
- Agent 运行状态不再混入任务待办，在审计项目内「Agent 运行记录」单独查看。

验收口径：

- 任务状态变化应更新时间并刷新缓存。
- 全局任务能跨审计项目查看待办。

### 3.11 系统后台

已实现：

- 只有 `is_system_admin=true` 用户可访问。
- 概览统计用户、审计项目、文档、任务、知识库等数量。
- 用户管理支持搜索、分页、排序、启停、系统管理员权限切换、重置密码、删除用户。
- 删除用户时会关联删除用户相关审计项目、文件、知识库等数据，并清理文件。
- 审计项目管理支持搜索、分页、排序和删除审计项目。
- 后台列表和概览使用短 TTL 缓存，业务变更后主动失效。

验收口径：

- 不能删除当前登录管理员自己。
- 不能让系统没有任何启用中的系统管理员。
- 重置密码不能看到旧密码，只能设置新密码。

## 4. 线上稳定性需求

大模型相关能力必须遵守以下原则：

- 文件解析、审计底稿生成、重写、翻译都要限制输入体积和输出 token。
- 审计人员应优先选择少量高价值事实和知识库，不要一次塞入全部材料。
- 前端应明确显示任务状态，避免用户误以为页面无响应。
- Worker 失败要记录错误，并允许用户重新发起。
- 对长时间停留在 `queued/processing` 的 Agent 任务，系统应按保护时间自动释放排队资源并标记失败。
- 文件解析和事实重解析应阻止同一文件或同一事实重复提交。
- Redis 失效时，列表缓存可降级为数据库查询；但 Celery 队列依赖 Redis，必须在运维层监控。
- 线上必须部署 API 和 Worker 两个服务；只部署 API 会导致解析、重解析、审计底稿生成和 AI 重写队列无人处理。

## 5. 数据与权限要求

- 审计项目、文件、事实、任务、报告都按审计项目成员校验访问权限。
- 知识库按审计人员本人隔离。
- 系统后台按系统管理员角色隔离。
- 公司/审计机构字段不参与业务筛选和权限判断。
- 上传文件存储在 S3-compatible 对象存储或本地 fallback 中，下载走后端鉴权。

## 6. 当前限制与后续待办

当前限制：

- 文件解析仍由审计人员手动触发；非常大的扫描件可能受 OCR 和远端模型速度影响。
- 组织/审计机构没有真正协作权限模型。
- 客户门户未实现。
- 线上监控目前依赖健康检查、Docker 日志和测试，未内置 Sentry/日志平台。
- 文档解析质量取决于文件可读性和大模型稳定性。

后续待办：

- Agent 运行记录接口增加真正的后端分页、按类别过滤和更多检索条件。
- 增加客户门户和客户补材料入口。
- 引入团队/审计机构级知识库共享与审批。
- 加入 Sentry、Uptime Kuma、外部备份告警。
- 对大 PDF、图片 OCR 增加页数选择和预览。
