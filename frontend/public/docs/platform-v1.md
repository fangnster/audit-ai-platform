# AI Agent 移民律师协作平台 V1.2 需求说明书

更新时间：2026-04-27

本文替代原根目录 Word/PDF 版本。后续需求、实现、部署和操作说明统一使用 Markdown 维护。

## 1. 当前定位

ImmigrationAI 是面向移民律师和案件助理的 AI Agent 工作台，用于把案件材料整理成可核验事实，再基于律师确认的事实生成或改写移民申请文案。

AI 输出只能作为草稿辅助，不能替代律师的事实核验、法律判断和最终审核。

## 2. 当前版本边界

- 客户门户未实现。客户信息由律师在案件中维护，补材料通过任务中心跟踪。
- 公司/律所名称保留在注册页和设置页，可展示、可编辑，但不参与业务权限和知识库筛选。
- 知识库只按律师本人筛选，不按组织或律所共享。
- 所有知识库入口只按标题和标签检索，不按正文内容检索。
- 文件上传后由律师手动触发后台 AI 解析，同一文件解析中会阻止重复触发。
- 事实异议重解析走后台任务，同一事实重解析中会阻止重复触发。
- 文档解析和事实重解析只允许选择提示词模板和 Agent 策略。
- 文案生成和 AI 重写可以使用提示词模板、文案模板、范文和 Agent 策略。
- 文案生成走 Celery Worker 异步任务，同一案件已有排队或处理中任务时会阻止重复生成。
- 每个案件内提供独立「Agent 运行记录」，位于案件任务后面，按文件解析和重解析、事实重解析、文案生成和 AI 重写分类展示状态、输入、结果、诊断和失败信息。
- 顶部告警栏提供成功/失败历史查询，设置页可按类别控制弹出和历史记录；告警历史中的名称优先使用原始文件名、事实内容、文案标题、案件名、任务名等源对象，避免只显示操作名称。
- Agent 任务超过保护时间仍未完成时会自动标记失败并释放按钮，允许重新触发；旧 Worker 晚返回不会覆盖新结果。
- 系统后台支持用户、案件、密码重置、管理员授权和删除操作。

## 3. 当前业务流程

```text
注册/登录
→ 设置个人信息、公司/律所名称和模型配置
→ 创建案件
→ 上传文件并选择文件类型
→ 手动触发 AI 解析
→ 审核、编辑、确认事实
→ 有异议时输入异议并重解析
→ 选择确认事实和少量知识库
→ 按章节生成文案
→ 律师审核、AI 重写、翻译、导出
→ 通过任务中心跟踪补材料和复核事项
```

## 4. Agent 使用原则

- 文件解析、文案生成、重写、翻译都要限制输入体积和输出 token。
- 大文件优先拆分，扫描件先 OCR。
- 文案生成按一个章节或一个论点发起，不一次生成完整请愿书。
- 单次生成优先选择 6-15 条确认事实和 1-4 条知识库。
- 点击生成或解析后到当前案件「Agent 运行记录」查看状态，不短时间重复提交。
- Worker 失败必须记录错误，律师应基于错误缩小输入后重试。

## 5. 线上部署和测试原则

- 线上必须同时部署 API、Worker、PostgreSQL、Redis 和对象存储；只部署 API 会导致解析、重解析、生成和重写任务无人处理。
- 生产 `.env` 中 `DEBUG=false`，并配置 `SYSTEM_ADMIN_EMAILS`、LLM、Redis、数据库和对象存储。
- 建议保留默认保护时间：排队 10 分钟、处理中 18 分钟、文案任务 7/8 分钟、解析任务 15/16 分钟。
- 每次上线前跑后端测试、前端构建和迁移；上线后做小文件解析、事实确认、文案生成和 Agent 运行记录检查。
